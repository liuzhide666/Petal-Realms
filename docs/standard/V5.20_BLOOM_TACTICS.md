# Normative Supplement S4 — Bloom and Tactics

This supplement specifies the V5.20 candidate. It extends the original 138 contracts with M139–M143. It is not a publication receipt. Schema 5, account identities, database bindings and the existing fixed crafting/drop coefficients remain compatible. The Library handbook's 354 historical pages are not rewritten by this Markdown supplement.

## S4-01 — Explicit save recovery

Login authenticates first, then compares the pending outbox's base revision with the returned cloud revision. Inequality blocks implicit overwrite and expands a local/cloud comparison in the gate. A revision mismatch alone does not prove another device signed in. The summaries show level, kills, bag quantity/family count, region, revision and available timestamps. These summaries cannot determine which build or inventory is more valuable.

Cloud choice exports the pending record and stores a local rollback copy before removing the outbox. If entry fails and no newer pending record exists, restore the original bytes. Never replace a newer generation during recovery. A download initiation is not proof the person retained a file.

Local choice rereads cloud state and verifies account identity. If the reviewed cloud revision or exact local pending bytes changed, show an updated comparison and require another explicit choice. Replacement still uses the fresh `expectedRevision`; a later concurrent writer can cause 409. No automatic merge, forced revision bypass, account reassignment or stronger distributed transaction is introduced.

## S4-02 — Conserved, single-acceptance crafting

One operation owns the current interface session and account until presentation completes or is canceled. Batch confirmation captures those identities and rechecks them before settlement. A stale confirmation, repeated activation or panel change cannot start a second settlement for the same accepted operation.

`craftBatch` remains bounded by five attempts. An attempt requires at least five unlocked source petals and a destination stack below 99999. Success consumes five and produces one; failure consumes a uniformly chosen one through four. Super forging remains guaranteed without a craft RNG draw. Stop before drawing randomness when destination capacity is exhausted. Outputs are not recursively consumed.

For probability p, stock n, remaining output capacity c and attempt index k, the analysis transitions `(n,w)` to `(n-5,w+1)` with p and `(n-j,w)` with `(1-p)/4`, j=1..4. States with `n<5`, `w>=c` or k=5 absorb. `craftAnalysis(p,n,attempts,c)` defaults c=5 for backward compatibility; the UI passes the actual available capacity capped at five. The independent replenished-material expectation `5+2.5*(1-p)/p` retains its separate scope and assumes output space exists. No pity state is added.

Settlement precedes a persistence attempt, which precedes presentation. The receipt reports actual attempts, successes, failures, source consumption, remainder and output; it distinguishes local-save success, guest mode and failed persistence. Cloud completion remains a separate save-status claim. Playback does not own inventory, consume RNG or grant results. Default visual duration is 950 ms, reduced mode 180 ms; skip, panel close and background transition finish presentation only. Results remain readable after skipping. Short landscape omits the decorative stage to preserve result readability.

## S4-03 — Skill state and visual semantics

Storm uses a fixed-radius fading afterimage of its instantaneous damage. Volley retains ten actual native projectiles, drawn along their true velocities. Heal uses inward leaves and an effective restoration receipt. Barrier and overdrive marks last exactly while their real `until` timestamps exceed simulation time. Barrier means damage reduction, not a new projectile collision wall. Buff labels and actual remaining seconds remain visible in reduced/low graphics; decorative strokes are reduced. Optional one-shot marks honor the particle toggle.

The transient skill-mark queue is capped at 12 and culled on simulation updates. Rendering reads immutable descriptors and never advances clocks, changes colliders or draws gameplay RNG. Pause freezes skill duration. Death, respawn and transitions clear transient presentation as specified by the runtime.

Full-health healing is declined before cooldown consumption. Otherwise `gain=min(maxHP-HP, nominalGain)` and feedback reports that effective gain. This is a deterministic eligibility/feedback change, not a healing coefficient increase. Existing skill coefficients and cooldowns remain 14/12/20/25/28 seconds.

## S4-04 — Isolated tactical training

Entry is available through Pause → Tactical Training. The player selects an explicit first-wave enemy level (1–993) and rank (0–7). Later waves add three levels each. HP and contact damage use the native species/level and Super multipliers, while rank retains native armor/special effects. No claim is made that every selected build/difficulty pair is balanced.

Before entry, non-guest main progress must save locally. Suspend the main runtime, including its world entity references and RNG closures; preserve mutable combo/camera values separately. Copy level, talents, settings and dual equipment into a distinct transient runtime. Leave experimental presence rooms. Trial saving is prohibited independently of the guest flag; kills give no main XP, loot, quests or guardian credit. No permanent reward ledger exists because there are no permanent training rewards.

Normal spawning and world events are disabled; the trial map has no rocks, portals or shrines. All waves use the same population ceiling 24. The circular arena radius is 620, with the player's real body radius subtracted for movement confinement. Marks indicate that boundary. Return, result dismissal and logout shortcuts restore the suspended main world and RNG and clear held input. A refresh ends training; it reloads the main save, not the suspended transient world. The trial itself is not crash-persistent.

## S4-05 — Two distinct objectives

Both modes have three waves and a 180-second simulation-time limit. Every wave has at least 1.5 seconds of spawn-position warning. If the player is within `mobRadius+playerRadius+80` of any planned spawn, the whole wave is delayed for another warning interval. No unannounced relocation is substituted.

**Surround:** start at full health. Three pressure sectors use native frontline ants, charging beetles and, in later waves, ranged wasps. The marked opening rotates by -pi/2 each wave. Wave completion requires both clearing enemies and crossing radius 260 within 0.62 radians of the opening. An obstacle-free initial center-to-opening corridor is checked against conservative enemy bodies and the maximum soil build radius 94. Moving enemies may later contest it; this is not a perpetual safety guarantee. Old hostile/friendly shots are cleared between waves.

**Last Stand:** start at rounded 35% max health. Across all waves, share exactly three accepted active-skill uses. Cooldowns still apply; rejected/full-health casts spend no use. Passive healing remains allowed and is an intentional build choice. This mode requires clearing waves, without Surround's breach objective. Skill controls cannot advertise exhausted actions as ready.

## S4-06 — Observations, models and limits

Trial effective damage sums capped direct HP loss plus capped poison tick loss. Accepted player HP loss excludes overkill and immunity rejection. Active-heal receipts count active skill restoration, not all passive recovery. Effective trial output per second divides recorded damage by combat-phase simulation time, including movement/reload downtime; it is not a global build ranking. Pauses and spawn-warning intervals do not contribute combat time.

`scripts/analyze-balance.cjs` executes source functions in isolated fixtures and produces a source-hashed report: progression, replenished independent craft Monte Carlo, finite-stock distributions, conditional single-hit moments, native monster spawn branches and EHP mitigation scalars. Fixed contact conditions are not observed DPS; modeled EHP excludes finite armor layers, grace, healing and positioning. No broad progression/rarity/reward retuning is certified by these diagnostics.

Required gates include the native account API suite, earlier inventory/geometry/input suites, new recovery/capacity/crafting/effect/training suites, five-viewport feedback checks and Worker compilation. Chromium emulation does not certify physical iOS Safari or low-end battery behavior. Shared-world authoritative combat, a trusted economy/leaderboard, pity, post-61 specialization and long-term balance remain separate work.
