# V5.16 Botanical Workshop - normative amendment

PR-STD-003, edition3.2. Runtime5.16.0. These implemented contracts extend the existing130 without changing their identifiers. Existing drop, critical, slow, crafting and save-schema coefficients remain unchanged.

## M131 - Normalized build preferences

**Equation:** z[k,j] = f[k,j]/max_available(f[:,j]); zero maximum gives z=0; s[k] = sum_j w[j]*z[k,j]

**Inputs:** Owned item keys, finite nonnegative features and one registered preference.

**Outputs:** Per-item dimensionless score and normalized weight tuple.

**Meaning:** The three features are base damage times rarity scale, base durability times scale divided by max(0.1,reload seconds), and rarity scale for a declared support-family tag, otherwise zero. Weights are attack=(.8,.15,.05), sustain=(.15,.35,.5), balanced=(.4,.3,.3). Normalize over the union of backpack and current deck keys.

**Composition:** Compute the same feature vector for preview and application; preference coefficients are not random probabilities.

**Boundary:** This additive preference ignores hit frequency, synergies, health penalties, crits, slows and enemy armor. It is not DPS or a global combat optimum.

**Verification:** Check all-zero feature domains, each policy and stable repeated previews.

**Anchor:** PetalWorkshop.plan; buildWorkshopPlan [S15]

## M132 - Inventory-constrained greedy build

**Equation:** n[k]=bag[k]+count_current(k); maximize sum_k x[k]*s[k] subject to 0<=x[k]<=n[k], sum_k x[k]=N

**Inputs:** Bag integer counts 0..99999, current deck and feature registry.

**Outputs:** Full N-slot proposal, remaining bag and before/after scores.

**Meaning:** Sort by descending per-copy additive score, then ascending ASCII item key; take the available copies until N slots are filled. The exchange argument proves optimality for this additive model: replacing any selected lower score by an available higher score cannot decrease the objective.

**Composition:** The backup deck is excluded from the pool. Exactly N current slots are filled, N in 1..10. No RNG is consumed by planning.

**Boundary:** An optimum of this preference model need not win a battle. Equal-score selection is deterministic and may rearrange the current deck.

**Verification:** Enumerate small bounded candidate pools and compare with exhaustive feasible allocations; assert preview purity.

**Anchor:** PetalWorkshop.plan [S15]

## M133 - Atomic equipment conservation

**Equation:** bag_new[k] + count_new(k) = bag_old[k] + count_old(k)

**Inputs:** Proposed bag/deck and current owner/view signature.

**Outputs:** Either unchanged state or one conserved replacement.

**Meaning:** Plan from a copy of inventory, preserve the backup deck, and check an owner/deck/bag/backup signature after confirmation. Commit the proposal only when the signature still matches. Reject any resulting stack above99999 rather than clamp away equipment.

**Composition:** All current slots are exchanged together; no intermediate takeBag/addBag sequence is exposed.

**Boundary:** This is a synchronous client transaction during a paused view. It is not a server-authoritative anti-cheat transaction or a cross-device lock.

**Verification:** Check each item key, cancellation, stale identity and unchanged backup; test a nearly-full returning stack.

**Anchor:** workshopIdentity; renderBuildWorkshop; PetalWorkshop.plan [S15]

## M134 - Build application reload and health clamp

**Equation:** cd_i=2.5 s; hp_i=0; player_HP_new=min(player_HP_old,maxHP(new_deck))

**Inputs:** Confirmed full deck and current nonnegative player HP.

**Outputs:** Reloading equipment and clamped current health.

**Meaning:** Applying a build uses the established equip reload path, recomputes synergies, view scale and HUD, then saves. It does not grant healing or immediate ready petals.

**Composition:** New cooldowns advance only after leaving the paused panel. HP cannot rise merely because the new deck has more maximum health.

**Boundary:** resetEquip also initializes shotWait using the world stream, as ordinary equip does. Only preview is RNG-free.

**Verification:** Assert all reloads equal2.5 at commit, HP nonincrease and persisted current/backup compatibility.

**Anchor:** resetEquip; renderBuildWorkshop; maxHP [S03]

## M135 - Gate-entry announcement lifecycle

**Equation:** gate_visible_entry -> welcome_open -> dismiss -> optional_session_restore

**Inputs:** Gate visibility and user dismissal events.

**Outputs:** One current welcome view and a resolved dismissal promise.

**Meaning:** Every initial load and transition back to the gate opens the developer/update announcement. Manual reopen is available. First session restoration waits for dismissal; a hidden gate closes a pending welcome. Repeated calls while open share the same close promise.

**Composition:** Gate visibility owns welcome presentation. Changing authentication tabs does not create a new gate entry.

**Boundary:** The developer text describes the project without inventing personal biography. No forever-hide preference suppresses subsequent gate entries.

**Verification:** Check first load, manual reopen, Escape, logout, focus and restored-session ordering.

**Anchor:** PetalUI.install; PetalUI.welcome; logout [S16]

## M136 - Validated announcement freshness

**Equation:** valid(feed) -> render_text(feed); fetch_failure -> retain(last_good or bundled)

**Inputs:** Untrusted same-origin JSON response and trusted bundled fallback.

**Outputs:** Sanitized release object, fetch timestamp and honest status.

**Meaning:** Fetch same-origin release.json without cache, with a5-second abort, maximum16384 decoded characters, schema1, numeric semantic version, ISO UTC timestamp and1..20 bounded highlights. Render text using textContent, never feed HTML.

**Composition:** Manual reopen/refresh and returning visibility request current published content. The bundled object must exactly match the checked-in release JSON at build time.

**Boundary:** This is current published release information, not developer presence or an unimplemented roadmap feed. A failed fetch visibly names cached/bundled fallback.

**Verification:** Reject malformed schemas, markup, oversized fields and invalid dates; exercise HTTP failure and successful refresh.

**Anchor:** PetalWorkshop.release; PetalUI.refresh; PetalUI.paintNews [S16]

## M137 - Guarded asynchronous confirmation

**Equation:** apply iff accepted AND owner,account,active,view,player,conflict identities remain equal

**Inputs:** Operation description, decision and captured owner/view state.

**Outputs:** Boolean acceptance bound to a stable operation context.

**Meaning:** A native dialog offers cancel as the initial focus. Escape rejects. The suspended operation resumes only if the account, player object and view still match the captured state. A second pending request rejects instead of replacing the active decision.

**Composition:** Apply this boundary to bulk crafting, talent reset, imports, restore, migration, conflict resolution and build application. A pre-existing conflict may be explicitly resolved; a newly changed conflict invalidates a stale action.

**Boundary:** Confirmation does not replace server ownership, revision checks or payload validation.

**Verification:** Test cancellation without mutation, initial cancel focus, stale owner and accepted guarded commit.

**Anchor:** askGame; PetalUI.ask [S16]

## M138 - Panel focus and presentation isolation

**Equation:** panel_open -> pause AND resetInputs AND inert(background); close -> resetInputs AND restore(canvas_focus)

**Inputs:** Viewport, focus, input event and panel state.

**Outputs:** Paused, navigable panel or unobstructed gameplay view.

**Meaning:** Shared panel header, navigation, materials, spacing and device breakpoints apply to inventory, equipment, crafting, skills, talents, stats, journal, map, codex, probability, preferences and help. Tab cycles visible panel controls; native top-layer dialogs own their own focus.

**Composition:** Reduced-motion media disables entry animation. Native input fields remain selectable. Decorative brand rings cannot intercept pointer input.

**Boundary:** These are presentation and interaction contracts. They do not change colliders, reward weights or authentication requirements. Hardware Safari remains outside synthetic Chromium coverage.

**Verification:** Inspect all14 panel types at five viewports including320x568 and568x320, with actual CJK fonts; verify body overflow and keyboard restoration.
