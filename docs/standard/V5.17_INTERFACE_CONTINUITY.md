# PR-STD-003 / Edition 3.2 / Supplement S1

## Scope and authority

This supplement specifies the V5.17 interface transition corrections. The 333-page Edition 3.2 remains a frozen V5.16 source inventory, not a census of V5.17 syntax. This supplement supersedes its overlapping presentation and input descriptions only. M001-M138 keep their identifiers and classifications. No new combat, loot, crafting, reward or preference-score distribution is introduced.

The normative implementation is `site/index.html`: `resetInterfaceState`, `showModal`, `closeModal`, `renderModal`, `renderPanelFooter`, `bindBagDrag`, `resetInputs`, `equipInto`, `initGame` and `logout`. The PDF supplement records exact source hashes; publication is a separate verification step.

## S1-01: Session-scoped presentation state

Let U = (menus, filters, selection, scroll positions, build preference). On an actual game initialization or completed logout, reset U to the collapsed menus, empty queries, all rarities, rarity ordering, first slot, current deck, no item preview, no craft selection, balanced preference and empty scroll-position map. Set both menu `aria-expanded` values to false. U is transient and is not a player-save schema extension.

## S1-02: Panel position ownership

Let q be the current panel and P[q] its stored vertical offset in CSS pixels. Before opening a panel or closing it, record its current offset. Opening q restores max(0, P[q]) subject to the browser's normal scroll-range clamp. An unvisited panel starts at zero. Rerendering a panel preserves its offset. A new session clears P. Offsets never control simulation time, inventory or RNG.

## S1-03: Semantic focus identity

Before rerendering, capture a focused control's DOM id or one of its stable data keys: equip, craft, slot, deck, policy or talent. After rendering, focus the surviving corresponding control with `preventScroll`. If a removed in-panel control has no successor, focus the panel close button. This is a presentation identity, not an account authorization token. Native modal dialogs retain their existing focus isolation.

## S1-04: Persistent equipment action

The bag footer is outside the scrolling panel body. It displays the selected item's rarity and family, the target current/backup deck and one-based slot number. Its action invokes the same `equipInto(key, slot)` path as the inspection workbench. It does not mint items or bypass insufficient-stock checks, backup-deck selection, the existing reload cost or the HP clamp. With no available selected item, disable the action. Other panels hide the footer.

For valid item k and replaced item j, the bag transition is b'[k] = b[k] - 1 and b'[j] = b[j] + 1, with the selected slot replaced by k. When j = k, the net bag count is unchanged. The sum of bag, current-deck and backup-deck counts is conserved per key, within the existing inventory domain. If k differs from j and the return stack b[j] is already 99999, reject the entire swap before taking k. A same-key swap at the cap is permitted because its net change is zero. This prevents silent loss of the replaced item.

## S1-05: Scroll and drag partition

Card bodies use vertical browser panning. A touch/pen drag begins only from the explicitly marked grip; the grip uses `touch-action: none`. Mouse native drag-and-drop remains available on the card. After grip displacement exceeds 12 CSS pixels, show a noninteractive drag ghost. A valid pointer-up over a slot in the same live bag root invokes equipment. Cancellation never equips. After a completed drag, suppress the generated card click for 500 milliseconds.

## S1-06: Drag lifetime and isolation

At most one touch drag owns global move/up/cancel listeners. Beginning a replacement drag, resetting game input, switching or closing panels, rerendering, window blur or page hide clears those listeners, ghost and highlights. A late pointer-up from a discarded drag cannot equip into a newly created panel. Unknown item keys and invalid slot indices remain rejected by `equipInto`.

## Probability and persistence boundary

For fixed valid state x and interface action a, the interface-only transition has kernel K(x'|x,a) = 1 for its determined successor. UI render, filtering, scrolling and focus restoration do not consume loot, craft or combat RNG. Equipment application retains its existing simulation-side reload behavior and must not be described as RNG-free. The only `ruleset.json` change is the version label. Account API behavior, database schema and save schema 5 are unchanged, apart from the health endpoint version.

## Verification and limits

`tests/browser_v517.mjs` exercises five Chromium viewports: 1280x800, 390x844, 844x390, 320x568 and 568x320. The suite verifies semantic keyboard focus, per-panel scroll ownership, footer visibility, equipment stock use and conservation on its bounded fixture, mobile browser touch panning, grip-only dragging, stale-drag cleanup, logout state reset and lack of runtime errors. The V5.16 regression suite continues to verify all 14 panels and the build workshop. CI additionally runs the existing account, recovery, CAS, controls, collision and probability tests. Emulation does not certify hardware Safari behavior or all possible save states.
