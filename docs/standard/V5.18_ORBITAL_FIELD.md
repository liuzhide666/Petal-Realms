# PR-STD-003 / Edition 3.2 / Supplement S2

## Scope and reference evidence

V5.18 introduces an original outline-art presentation profile. It does not claim to reproduce Florr's complete interface, assets, server logic or numerical rules. On 22 October 2026 the official https://florr.io/ page was opened in the browser. The guest entry, animated floating-petal background, green ground and top-left utility icons were directly visible. After the guest action the page stayed on Connecting and logged "Ran out of transport methods to try". One reload and guest retry did not establish a playable session. Combat, map layout, enemy behavior, crafting odds and settings beyond that screen were not verified. A generic transport failure is not evidence of bot detection.

The original 333-page standard and Supplement S1 remain source-frozen descriptions of earlier versions. S2 governs the V5.18 presentation changes below; their old syntax ledgers must not be called a census of V5.18. All 138 existing mechanism identifiers and status classifications remain registered. No combat or reward probability coefficient changes.

## S2-01: Bounded presentation profile

The settings projection accepts visualStyle in {field, botanical}, hud in {compact, full}, motion in {auto, reduced}, and strict Boolean showGrid and orbitGuide. Missing or invalid values map respectively to field, compact, auto, false and false. This projection runs when a save enters the game and after presentation selection. It extends the existing settings object inside save schema 5, not the account identity, database schema or progression model. Effective reduced motion is the logical OR of the operating-system media preference and motion == reduced.

## S2-02: Rendering-state separation

Let G be the gameplay state, U the presentation profile, t the presentation clock and I the output image. Rendering is I = R(G,U,t), with G unchanged. Rendering, thumbnails and settings projection must not draw from the world, loot, craft, combat or visual gameplay streams. Deterministic terrain decoration uses a private local LCG, s[n+1] = (1664525*s[n] + 1013904223) mod 2^32. Its seed is the existing biome seed plus 813. This private decoration sequence is not a drop distribution or probability-balance source. Presentation caches are keyed by both style and biome to prevent cross-style material reuse.

## S2-03: Shared original artwork and scale

All 29 registered petal families use one original procedural outline renderer for world art and the inventory, forging, workbench and equipment thumbnails. World size remains the existing petal size times PETAL_WORLD_SCALE. UI thumbnails are rasterized from the same vector paths onto their own high-resolution canvas; icon dimensions never change a collider. The eight field biome palettes are distinct. Both world and thumbnail creature rendering use the existing species body ellipses, anatomy and size. The optional target canvas is passed explicitly so a codex portrait cannot write onto the world canvas. Decorative legs, wings, crowns and tails remain outside collision semantics.

## S2-04: Clock and motion policy

Avatar gaze uses existing velocity, blink uses a deterministic sine phase, and hurt expression uses the existing last-hit clock. None modifies movement or HP. Creature locomotion phase remains derived from simulation time, species speed and identity. Reduced motion freezes optional blink, creature gait, portal spin and bob, loot bob, gate drift and UI transitions. It does not freeze combat, authoritative projectiles, orbital collision motion, cooldowns or danger telegraphs. The gate drift clock comes from performance.now without advancing game.time. Motion preferences must not become an advantage in crafting or loot odds.

## S2-05: HUD and backup-deck access

Compact HUD retains HP, XP, save status, biome information where space permits, map access, inventory access, skill access and pause. Extra numeric panels and tools are disclosed through existing menus. Colored equipment cards retain the rarity label through accessible names and show current durability/reload state. On fine-pointer desktop layouts the backup strip opens manual equipment for the selected backup slot; it does not perform a combat deck swap, consume an item or bypass the existing reload cost. Coarse-pointer layouts retain backup access through the bag and hide this extra strip to protect movement controls.

## S2-06: Optional guides and gameplay invariants

The grid is visual only. The orbit guide uses the actual distance between the first live petal and player, not a replacement collision or attack-radius formula. Field biome rings retain positional rarity-band information without the large world-text plaques; the HUD and map remain the information sources. No viewport resize, style switch, glyph replacement or portrait rendering may alter mobCollider, petalContactRadius, damage, hit ordering, crafting, drops, save revisions or inventory conservation. Existing constraints and failure boundaries continue to apply.

## Verification and limitations

The browser suite uses 1280x800, 390x844, 844x390, 320x568 and 568x320 Chromium viewports. It checks settings controls, sanitization defaults, compact/full disclosure, all 29 petal thumbnails, 43 codex portraits, world-pixel isolation of thumbnails, gameplay-state and RNG preservation, backup-slot routing, eight biome views and 129 species-size collider comparisons. Existing V5.16 and V5.17 regressions continue to cover panels, native dialogs, scrolling, touch grip behavior and safe equipment return stacks. Emulated Chromium does not certify physical Safari behavior. The unavailable Florr gameplay session prevents any claim of verified one-to-one gameplay parity.
