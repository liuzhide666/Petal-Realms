## Material constraints

## Crypto runtime hotfix (after user signup failure)

The earlier Pages health check only queried D1, and its success did not prove the 600000-iteration password path worked. A deployed fixed-data Worker reproduced the PBKDF2 100000 ceiling; Node and local workerd did not enforce it. The regression failed 503 before the fix. Native scrypt N=16384,r=8,p=5 succeeded remotely and matched the Node fixed vector. The handler now uses this standard profile for new and recovered passwords, retains explicit old-record recovery and checks crypto in health.

Fresh local full suite: 17 static CJS scripts and 12 API tests passed; Worker compilation passed. Previous 105 browser checks are historical evidence for the preceding commit, not fresh post-fix results. Revised Pages crypto health and browser acceptance must be recorded separately.
