# V5.11 · Cloudflare accounts and cloud saves QA

## Target and evidence boundary

Baseline: main 7a083b406ee7988a4eb63742a68617bcc7f4c6dc, V5.10.

This release changes account/storage and retirement configuration. It retains the existing game content and legacy role access. Production status must be checked against provider deployment SHA, not this source version label.

## Executed checks

- New account API tests use real native crypto and SQLite against the Functions handler, including server identity assertions, CAS races, limits, recovery rotation, cross-user saves and verified mocked legacy migration.
- Whole-branch independent review found four material lifecycle/integrity bugs. The original behavior was reproduced with failing tests before the fixes; three extracted-client tests plus a cross-tab API case cover them.
- Real local workerd+D1 browser acceptance: 21/21 after fixes, including secure session, two independent device contexts, import/upload, stale-write rejection, explicit cloud resolution, password revocation, incorrect/correct recovery, local migration and same-origin second-tab exclusion.
- Retained local-account browser regression: 32/32. Existing gameplay UI: 28/28. Baseline desktop/mobile: 10/10. Mocked old cloud login/outbox: 7/7. These tests exercise explicit legacy modes; they do not create production users.
- Final full suite: 16 CJS scripts (including 3 review regression cases), 9 API tests, and Worker compilation passed after fixes. Browser checks total 98 across the five groups. GitHub CI reruns the static/API suite plus existing and new runtime browser acceptance.

## Infrastructure actually changed

Created petal-realms-accounts and petal-realms-accounts-preview D1 databases and applied the additive initial schema through Cloudflare API. No Supabase user payload was copied, changed or deleted. Actual production/preview binding and deployment are separate release gates.

## Not yet verified / not implemented

- Real old Supabase user's migration; requires the owner's authenticated session. Tests use controlled mocks or local roles.
- Native Safari/HarmonyOS endurance and real internet cross-device latency.
- Production native-crypto CPU/request quota behavior until Cloudflare preview acceptance.
- Remote Netlify deletion/repository unlink, unavailable in the current connector. The remaining ignore file only stops builds.
- Server-authoritative combat, rewards, trading, full multiplayer and broad Florr-inspired gameplay/content expansion.

## Material constraints

One active same-origin browser tab per account uses Web Locks. Another device/browser context is allowed and uses server revision checks; an old browser without Web Locks retains local play. New account writes are gated by verified session identity and X-Petal-Account assertions; a caller cannot choose an owner merely by supplying an ID. Credentials, cookies and recovery codes never appear in progress exports.
