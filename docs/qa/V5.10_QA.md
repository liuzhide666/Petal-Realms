# V5.10 · Access and petal workbench

## Contract
- Cloudflare `https://petal-realms.pages.dev` is the only canonical runtime/release/callback origin.
- Default local account/password entry sends no email. Local and cloud identity/storage stay explicitly separate; no automatic verification bypass or cloud save migration.
- Existing remembered cloud sessions and old local password hashes remain compatible.
- New local accounts confirm an 8-character minimum password; passwords never appear in exported progress.
- Persisted mail cooldown honors `Retry-After` seconds and HTTP dates. A project email-limit response suppresses both local signup and recovery sends until that deadline; password login is independent. There is no automated resend loop or assertion that expiry restores provider quota.
- Local progress import validates type/size/version/numbers, asks before replacing and keeps a pre-import rollback. Cloud manual backup files cannot be imported as local character envelopes by accident.
- Flower workbench previews base quality stats against selected equipment; confirmation and desktop drag both preserve inventory return semantics. Material locks and conservative monster broadphase from V5.9.3 are retained.
- Netlify builds are skipped via `ignore`; the previous site and existing browser data were not deleted.

## Official source check (2026-10-18)
- https://supabase.com/docs/guides/auth/auth-smtp : default SMTP only sends to pre-authorized project-team addresses; currently two messages/hour per project; no delivery SLA. Custom SMTP initially has 30 messages/hour and its own provider limits.
- https://supabase.com/docs/guides/auth/rate-limits : default signup/recovery cooldown is 60 seconds per user; API/IP limits can independently return 429; actual project quotas may be customized.
- Auth policy/SMTP are not changed by this frontend release. An unconfirmed cloud identity never becomes verified merely because a rate limit is encountered.

## Remaining limits
- A local account is browser-local: losing its browser data without an exported backup loses that local progress. It is not cross-device cloud identity.
- Real SMTP delivery, two-device Supabase save synchronization and native iOS/HarmonyOS long-play remain unverified. Isolated browser tests use no production accounts.
- Cloud saves remain client-authoritative; multiplayer remains position-only preview.
