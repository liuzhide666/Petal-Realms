# Petal Realms V5.9.1 — Bulk crafting QA

Date: 2026-10-17.

## Changes
- Added a bounded **maximum-five-attempt** bulk craft option. A player must explicitly confirm before consuming any petals.
- Batch control activates only if selected petal type and rarity have at least 10 copies and the rarity is craftable.
- Every attempt independently uses the pre-existing per-tier chance. Success removes exactly 5 source petals and adds 1 next-tier petal; failure removes 1–4 source petals (uniform discrete distribution as originally implemented).
- Abort early when source inventory is less than 5. Enforce maximum of 5 attempts regardless of externally supplied `requested`.
- No auto-crafting next rarity, no change to one-off craft probabilities, save format, drop rates, user accounts, login or backend schema.
- A single save operation follows the completed batch; toast reports attempts, success, failure and material consumption.

## CI acceptance
- `node tests/v591_batch_craft.cjs` deterministically covers success, failure, max-five cap, insufficient stock, guaranteed forging, invalid input, top rarity, nonnegative inventory and single vs batch logic.
- Existing V5.9 creature/collider/auth tests remain active.
- Browser V5.9 test checks `batchCraft` button in desktop and mobile crafting panels.
- GitHub static checks, browser checks and Cloudflare exact production commit verification required before publishing.

## Unverified
- Actual physical touch screen long-term ergonomics, genuine email SMTP delivery and cross-device Supabase save synchronization remain unverified. Browser integration uses simulated gameplay, not real user items.
