# V5.17 interface continuity QA

Baseline: main `954f7312141a23f4fbe6d1a8ecf0300594d4049e` (V5.16).

## Reproduced failures

The new browser suite first ran against V5.16: 51 of 70 checks failed for the intended behavior, including lost card/slot keyboard focus, shared panel offsets, menus and selection surviving logout, and a card-body swipe creating a drag ghost. The persistent equipment footer and explicit touch grip were new acceptance checks.

## Local result

- V5.17 browser: 128 / 128 checks passed across five viewport sizes, including actual Chromium touch-event panning and discarded-drag isolation. A second RED case proved that a full return stack silently lost an item; all five viewports now verify atomic rejection and same-key swaps at the cap.
- Full static and native API suite: passed; 12 API tests, no production account created.
- V5.16 browser: 245 / 245 checks passed. Worker build: compiled successfully.
- Screenshot inspection: phone, desktop and short landscape; readable CJK typography, footer fits, scrolling content remains inside the panel.

The V5.12 touch regression now initiates drag from the explicit grip. It still verifies cancellation, successful drop and ghost cleanup. Other older expectations remain intact.

## Scope limits

Chromium mobile emulation is not hardware Safari testing. Public byte/hash and health checks verify publication separately from local interaction tests. No production player records or database schemas are changed by this release.
